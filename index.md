# Leading Analytical Work: Review, Standards and Stakeholders

قيادة العمل التحليلي: المراجعة والمعايير وأصحاب المصلحة

Data Science Track · 3 teaching days + capstone day · 21 hours · Level 400

Set the unit's quality standard, run review as a system, and hold the line on evidence with sponsors

Participants lead the analytics unit of the fictional Ras Sahil Ports Authority: twelve analysts whose work increasingly starts as an assistant's draft. They write a proportionate quality-assurance standard and review checklist, re-run and review colleagues' analyses, set the unit's rules for AI-assisted work, turn review findings into feedback, and negotiate scope, deadline and evidence with role-played sponsors, one of whom asks for an unfavourable result to be dropped. DS-310 teaches reviewing one analysis; this course sets the standards and runs the system.

**Who it is for:** Specialists. Data scientists who have completed the level 300 core and practicum, or can show equivalent work: an analysis they led from question to recommendation and defended.

**Format:** Intensive: 3 teaching days of four sessions and a capstone day, with guided pre-work and a tracked follow-up task

## The case study

**Ras Sahil Ports Authority.** Ras Sahil Ports Authority is a fictional Gulf-coast port authority whose analytics unit of twelve analysts serves marine operations, commercial affairs, finance and staffing, with more and more work starting as a draft by Musawwada, the unit's drafting assistant. Participants, as the unit's head, write the assurance standard from a log of 30 requests, adapt a published checklist, re-run a colleague's cargo-dwell repository, set rules for assisted work and audit five assisted analyses, calibrate severity with a second reviewer on a seeded-flaw berth-delay analysis, write feedback and a review rota, and negotiate scope, evidence and a pressured subgroup finding with two role-played sponsors. The capstone is the quality-assurance pack for the marine pilot staffing analysis. All data is synthetic and generated with a fixed seed.

## The course

### Day 1: Set the standard

Slides: https://sdaiaacademy.github.io/ds-407/slides/day1.md

- **Session 1: Assurance proportionate to risk**
  - Explain the four assurance roles and why the assurer is independent of the analyst
  - Grade a request by the effect of an error and the complexity of the work
  - Assign an assurance level with a matrix a peer applies the same way
  - [Lab 1.1: Six requests, four levels (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D1_1_assurance_levels.ipynb)
- **Session 2: A team review checklist**
  - Adapt a published checklist to the unit's work instead of adopting it whole
  - Write each item as a question answered with evidence
  - Tie each item to the assurance levels, with a privacy and classification check in every level
  - [Lab 1.2: A checklist adapted from REFORMS (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D1_2_team_checklist.ipynb)
- **Session 3: Reproducibility as a team rule**
  - Re-run an analysis from its repository before reading its conclusions
  - Classify reproduction failures by kind
  - Write repository rules that make a re-run routine
  - [Lab 1.3: Re-run Saleh's repository (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D1_3_rerun_repository.ipynb)
- **Session 4: Rules for AI-assisted analysis**
  - Turn the national generative AI guidelines into rules for analytical work
  - Specify the process evidence each analyst keeps
  - Test a rule set on real cases before adopting it
  - [Lab 1.4: Rules for assisted work (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D1_4_ai_rules.ipynb)

### Day 2: Review and develop

Slides: https://sdaiaacademy.github.io/ds-407/slides/day2.md

- **Session 1: Calibrating reviewers**
  - Rate review findings by their effect on the decision
  - Measure agreement between two reviewers, beyond chance
  - Turn disagreements into clearer checklist wording
  - [Lab 2.1: Two reviewers, one analysis (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D2_1_calibrate_reviewers.ipynb)
- **Session 2: Auditing assisted work**
  - Audit work against rules from its evidence, not its claims
  - Recompute a number an assistant drafted
  - Record each breach with the rule it breaks
  - [Lab 2.2: Audit five assisted analyses (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D2_2_audit_assisted.ipynb)
- **Session 3: Feedback that builds skill**
  - Choose the findings worth raising with an analyst
  - Write feedback that names the reasoning, not only the error
  - Plan development with goals, evidence and unaided practice
  - [Lab 2.3: Feedback and a three-month plan (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D2_3_feedback_plan.ipynb)
- **Session 4: Review capacity and mentoring**
  - Estimate a quarter's review hours from assurance levels
  - Assign reviewers under separation and seniority rules
  - Use review pairings to develop analysts
  - [Lab 2.4: A quarter's review rota (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D2_4_review_capacity.ipynb)

### Day 3: Work with sponsors

Slides: https://sdaiaacademy.github.io/ds-407/slides/day3.md

- **Session 1: Scope and deadline**
  - Size questions against a deadline, review time included
  - Offer options when a request cannot be met as asked
  - Record what was agreed and what was not
  - [Lab 3.1: A result in a week (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D3_1_scope_deadline.ipynb)
- **Session 2: Agreeing the evidence first**
  - Write the decision rule before the analysis
  - Check an evidence threshold against what the data can detect
  - Record roles and sign-off in the agreement
  - [Lab 3.2: An analysis agreement (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D3_2_analysis_agreement.ipynb)
- **Session 3: Pressure on a finding**
  - Tell a legitimate challenge from pressure to suppress
  - Respond with options that keep the finding
  - Record a decision with its reasons and references
  - [Lab 3.3: Drop the feeder result? (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D3_3_pressure_finding.ipynb)
- **Session 4: Reporting quality and correcting errors**
  - Write a quality statement a board can read
  - Correct a released figure quickly and openly
  - Link a correction to the change in process
  - [Lab 3.4: A quality statement and a correction (25 min)](https://sdaiaacademy.github.io/ds-407/labs/D3_4_quality_correction.ipynb)

### Capstone: Capstone: the staffing pack and the review meeting

## Capstone

A quality-assurance pack for one high-risk analysis (applied standard, review report, analysis agreement, board quality statement), submitted as a repository, followed by a fifteen-minute review meeting the participant chairs with a role-played analyst and sponsor

**What you submit:** A public GitHub repository link holding the pack (the applied standard, the review report, the analysis agreement and the board quality statement) with its commit history; then a fifteen-minute review meeting the participant chairs with a role-played analyst and sponsor, observed against a rubric.

**Rubric:**

- Standard: 20%
- Review findings: 30%
- Analysis agreement: 20%
- Quality statement: 20%
- Clarity: 10%

## Outcomes

- **LO1** Design a proportionate quality-assurance standard for analytical work, with assurance levels, a review checklist and sign-off rules, given the unit's log of 30 requests with their uses and risks (Performance) Evidence: a standard with which a peer, working independently, assigns the same assurance levels to six new requests
- **LO2** Review analyses by others, including assistant-drafted ones, rank findings by their effect on the decision and calibrate severity with a second reviewer, given three seeded-flaw analysis repositories (Performance) Evidence: review notes that find the seeded critical flaws, and a severity agreement table with the second reviewer
- **LO3** Design rules for AI-assisted analysis covering verification, disclosure and the process evidence each analyst keeps, and audit the unit's work against them, given the national generative AI guidelines and a log of the unit's assisted analyses (Performance) Evidence: a one-page rule set and an audit of five assisted analyses against it
- **LO4** Prepare feedback and a development plan for an analyst from review findings, given a reviewed notebook and the analyst's skills profile (Applied) Evidence: a feedback note and three-month plan that a peer judges specific
- **LO5** Lead a negotiation with a sponsor on scope, deadline and evidence threshold and record the agreement, given a role-played sponsor whose constraints change during the meeting (Performance) Evidence: an analysis agreement and an observer's rubric score
- **LO6** Decide how to respond to pressure to change or suppress a finding, and record the reasons, given a scripted request to remove an unfavourable subgroup result (Performance) Evidence: a decision record citing the unit's standard and the ethics principles

## Tools

- **Notebooks and reports:** Jupyter, marimo, Quarto
- **Code and document review:** pull or merge requests on GitHub or GitLab, comments in a shared document
- **Reproducible environments:** uv with a lock file, containers
- **Assistant whose output is reviewed:** a free hosted open-weight model, the assistant the participant's unit already uses

## Prerequisites

- DS-310 Problem Framing and Analytical Review
- Has reviewed an analysis written by someone else and written comments the author acted on
- Uses version control for analysis code
- Setup: a laptop processor with uv, or Google Colab. Nothing downloads a model; a free hosted model key is optional (every assistant and tutor cell has a stand-in). Run 00_setup_check before Day 1; see labs/README.md.
